# Atlas Phase 1 — Local Workspace

## Goal

Deliver a human-controlled desktop engineering workspace that can safely open a local repository, inspect and edit files, run terminal processes, and expose Git state. AI assistance may propose actions, but it cannot execute autonomous changes in this phase.

## Architecture decision

Use a Tauri desktop host with a React/TypeScript workspace UI. Keep operating-system access behind typed commands and events. The existing Next.js contractor product remains isolated from Atlas.

## Milestones

### 1. Trusted workspace core

- Workspace identity, trust state, and write policy.
- Path containment for every filesystem operation.
- Real-path checks to prevent symlink escapes.
- Optimistic concurrency for writes using content hashes.
- File size and binary-file limits.

### 2. Desktop shell

- Tauri application package.
- Native directory picker.
- Recent-workspace persistence.
- One active workspace per window.
- Crash-safe restoration without silently trusting moved directories.

### 3. Editor workspace

- File tree with refresh and filesystem watcher events.
- Monaco text editor with dirty-state tracking.
- Tabs, save, save all, close, and external-change conflicts.
- Search by file name and text.

### 4. Terminal and Git

- Explicit user-started terminal sessions.
- Process terminate and cleanup behavior.
- Git branch, status, diff, stage, unstage, commit, and checkout adapters.
- No shell command generated by a model may execute without human approval.

## Acceptance criteria

1. Atlas cannot read or write outside the selected workspace through `..`, absolute paths, symlinks, or malformed input.
2. Opening an untrusted workspace does not run scripts, extensions, tasks, terminals, or Git hooks.
3. A changed-on-disk file cannot be overwritten silently.
4. Closing a workspace terminates its watchers and terminal processes.
5. The editor, terminal, and Git panels use the same workspace identity and event stream.
6. Unit tests cover Windows and POSIX path cases.

## Out of scope

- Autonomous code modification.
- Background agents.
- Hosted model routing.
- Extension marketplace.
- Remote development.
- Multi-user collaboration.
